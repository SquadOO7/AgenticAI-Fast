## Setup

### Environment Variables

Create a `.env` file in your `config/` directory (or wherever your `GlobalState` expects it, but `config/.env` is a common pattern) based on `config/.env.example`.

```ini
# config/.env
X_BEARER_TOKEN="YOUR_X_BEARER_TOKEN"
BASE_URL="https://api.twitter.com/2" # Usually this, but confirm with X API docs
VERTEX_CREDENTIALS_FILE="path/to/your/service-account-key.json"
VERTEX_PROJECT_ID="your-gcp-project-id"
VERTEX_TOPIC_ID="your-pubsub-topic-id"
VERTEX_DATA_FILE="path/to/your/mock_data.json" # e.g., services/x_twitter/mock_feeds.json
```

  * **`X_BEARER_TOKEN`**: Your Bearer Token from your X Developer App.
  * **`BASE_URL`**: The base URL for the X API v2 (usually `https://api.twitter.com/2`).
  * **`VERTEX_CREDENTIALS_FILE`**: The absolute or relative path to your Google Cloud Service Account JSON key file.
  * **`VERTEX_PROJECT_ID`**: Your Google Cloud Project ID.
  * **`VERTEX_TOPIC_ID`**: The ID of your Pub/Sub topic where data will be published.
  * **`VERTEX_DATA_FILE`**: Path to a JSON file containing mock data to be published by the `/publish-random-feeds` endpoint.

### Google Cloud Setup

1.  **Create a Google Cloud Project:** If you don't have one, create a new project in the Google Cloud Console.
2.  **Enable Pub/Sub API:** Navigate to "APIs & Services" -\> "Enabled APIs & Services" and ensure "Cloud Pub/Sub API" is enabled.
3.  **Create a Pub/Sub Topic:** Go to "Pub/Sub" -\> "Topics" and create a new topic (e.g., `bengaluru-feeds`). Note its ID.
4.  **Create a Service Account:**
      * Go to "IAM & Admin" -\> "Service Accounts".
      * Create a new service account.
      * Grant it the "Pub/Sub Publisher" role (or a custom role with `pubsub.topics.publish` permission).
      * **Create a new JSON key** for this service account and download it. Store this file securely and provide its path in `VERTEX_CREDENTIALS_FILE`.

## Running the Application

### Running Locally

To start the FastAPI server:

```bash
uvicorn main:router --host 0.0.0.0 --port 8000 --reload
```

  * `main:router`: Assumes your main FastAPI instance is named `router` in `main.py`. Adjust if different.
  * `--host 0.0.0.0`: Makes the server accessible externally (important for `ngrok`).
  * `--port 8000`: Runs the application on port 8000.
  * `--reload`: (Optional) Automatically reloads the server on code changes.

Your API will be accessible at `http://localhost:8000`.

### Exposing with ngrok (Optional but Recommended)

If you need to test webhooks, expose your local API to external services, or share it with others, use `ngrok`.

1.  **Ensure ngrok is installed and authenticated:**
    ```bash
    ngrok config add-authtoken <YOUR_NGROK_AUTH_TOKEN>
    ```
2.  **Start your FastAPI app** (as shown above).
3.  **In a new terminal**, run ngrok to expose your FastAPI port:
    ```bash
    ngrok http 8000
    ```
    ngrok will provide public `http` and `https` URLs (e.g., `https://xxxx-yyyy-zzzz.ngrok-free.app`) that tunnel to your local FastAPI application.

### Running the `chron.py` script

The `chron.py` script is designed to periodically hit the `/publish-random-feeds` endpoint. Ensure your FastAPI app is running first.

```bash
python chron.py
```

This script will run indefinitely, hitting your API every 15 seconds. Press `Ctrl+C` to stop it.

## API Endpoints

Once the FastAPI application is running (e.g., at `http://localhost:8000` or your ngrok URL), you can access the following endpoints:

  * **Interactive API Documentation (Swagger UI):**
    `http://localhost:8000/docs`

  * **Fetch Feeds by X Handle:**
    `GET /fetch-handle-feeds`

      * **Query Parameter:** `handle_name` (string, required) - The X username (e.g., `narendramodi`, `elonmusk`)
      * **Description:** Fetches the last 7 days of tweets for a given X user handle and saves them to `bangalore_feeds.json`.
      * **Example:** `http://localhost:8000/fetch-handle-feeds?handle_name=BengaluruCity`

  * **Get Bengaluru City Feeds from X:**
    `GET /bengaluru-feeds`

      * **Description:** Fetches comprehensive public tweets related to Bengaluru for the last 7 days, categorizes them, and returns the data. It handles pagination up to 2 pages (can be configured in `services/x_twitter/operation.py`).
      * **Example:** `http://localhost:8000/bengaluru-feeds`

  * **Publish Random Feeds to Pub/Sub:**
    `POST /publish-random-feeds`

      * **Description:** Loads data from `VERTEX_DATA_FILE` (e.g., a mock JSON file) and publishes a randomly selected entry to your configured Google Cloud Pub/Sub topic.
      * **Example:** `http://localhost:8000/publish-random-feeds` (Send a POST request, e.g., via curl or Postman, though it doesn't require a request body).
